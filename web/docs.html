THE FRONTEND FIELD GUIDE

Your UI. A real API.

Run your frontend on its usual port and send requests to this server. No API key is needed. Products persist in the server’s SQLite database.

OpenAPI specification · Download the fetch client · Try the playground

1. Make your first request

BEFORE YOU START

Set up your frontend folder

Create a new folder for your frontend. Inside it, create two files: index.html and app.js. Download api.js into the same folder. Your folder should look like this:

my-frontend/
├── index.html   ← your page
├── app.js       ← your JavaScript
└── api.js       ← download from this server

Serve over HTTP, not file://. Open a terminal in your folder and run:

python -m http.server 5173

Then visit http://localhost:5173. Double-clicking the HTML file uses file://, which blocks JavaScript modules in most browsers.

The default API base URL is http://localhost:8080. If you changed the server address, use that address instead. Local frontends can access it with the default CORS configuration.

Paste this into your index.html to see it work:

<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>My products</title>
  </head>
  <body>
    <h1>Products</h1>
    <ul id="products"></ul>
    <script type="module" src="app.js"></script>
  </body>
</html>

And paste this into your app.js:

import { createClient } from "./api.js";

const api = createClient("http://localhost:8080");

const { data } = await api.list();
const list = document.querySelector("#products");
for (const product of data) {
  const item = document.createElement("li");
  item.textContent = `${product.name}: $${product.price.toFixed(2)}`;
  list.appendChild(item);
}
console.log(data);

Refresh the page. You should see the product list. If it is empty, create a product in the playground first.

Why type="module"?

The api.js file uses export to share its code. Your app.js uses import to load it. These keywords only work inside JavaScript modules. You tell the browser a file is a module by writing <script type="module"> instead of a plain <script> tag. Without type="module", you will see errors like:

Uncaught SyntaxError: Unexpected token 'export'
Uncaught SyntaxError: await is only valid in async functions and the top level bodies of modules

Modules also allow await at the top level of a file, which is why the snippets above work without wrapping everything in an async function.

Raw fetch (without the client helper)

If you want to understand what happens under the hood, this is the equivalent using the browser's built-in fetch function:

const response = await fetch("http://localhost:8080/products");
const payload = await response.json();
if (!response.ok) throw new Error(payload.error.message);

console.log(payload.data); // An array, including when empty
console.log(payload.meta); // page, limit, total, total_pages

This code still needs type="module" because of the top-level await. Put it inside a <script type="module">...</script> tag or a .js file loaded as a module.

2. Learn the routes

MethodEndpointResult
GET/products200 · List with pagination metadata
GET/products/{id}200 · One product
POST/products201 · Created product + Location header
PUT/products/{id}200 · Replace writable fields
PATCH/products/{id}200 · Change supplied fields only
DELETE/products/{id}204 · No response body
GET/health200 · Database is available

Use the returned product ID, rather than assuming IDs start at 1. Unknown products return 404. Unsupported methods return 405 with an Allow header. GET routes also support HEAD; known routes support OPTIONS.

3. Create, replace, or patch

POST and PUT require name and price. The description defaults to an empty string. Send Content-Type: application/json.

{
  "name": "Notebook",
  "price": 4.5,
  "description": "A dotted notebook."
}
  • name: 1–100 Unicode characters after trimming whitespace.
  • price: a JSON number from 0 to 1,000,000; at most two decimal places. Zero is valid.
  • description: at most 1,000 Unicode characters after trimming. Send "" to clear it.
  • id: assigned by the server. Do not include it in request bodies.

Unknown fields, incorrect types, and explicit null values are rejected. Bodies must be a single JSON object of at most 64 KiB. Field names are case sensitive.

PUT replaces: send name and price; an omitted description is cleared. PATCH changes: send at least one writable field; omitted fields are preserved. A PATCH body is a partial JSON object such as { "price": 0 }, not JSON Patch or JSON Merge Patch. Neither method creates a missing product.

Successful writes and single-product reads put the product inside data:

{
  "data": {
    "id": 1,
    "name": "Notebook",
    "price": 4.5,
    "description": "A dotted notebook."
  }
}

4. Give errors a useful home

Malformed JSON, invalid IDs, and bad query parameters return 400. Invalid product fields return 422 with messages you can show beside inputs:

{
  "error": {
    "code": "validation_error",
    "message": "Please fix the highlighted fields.",
    "details": { "price": "Must be between 0 and 1000000." },
    "request_id": "example-request-id"
  }
}

Use error.code for logic and error.message for feedback. Field messages live under error.details, which is optional. The request ID also appears in X-Request-ID.

StatusCodeAction
400invalid_json / invalid_id / invalid_queryCorrect the request
404product_not_found / route_not_foundShow a missing-item state or check the URL
405method_not_allowedUse a supported method
413payload_too_largeKeep the body within 64 KiB
415unsupported_media_typeSet the JSON Content-Type header
422validation_errorShow field errors and keep entered values
500internal_errorShow a retry action and keep the request ID
503service_unavailableThe health check cannot reach the database

5. Search and paginate

const params = new URLSearchParams({
  page: 1, limit: 5, q: "notebook", sort: "price", order: "asc"
});
const response = await fetch(`http://localhost:8080/products?${params}`);
const payload = await response.json();
if (!response.ok) throw new Error(payload.error.message);
console.log(payload.data, payload.meta);

Defaults: page=1, limit=10, sort=id, order=asc. Page accepts 1–1,000,000; limit accepts 1–100. Sort by id, name, or price; order is asc or desc. Search up to 100 trimmed characters in name and description. Search and name sorting ignore ASCII case; other language case folding is limited by SQLite. Unknown or repeated parameters return 400.

Metadata contains page, limit, total, and total_pages. With no matches, data is [] and total_pages is 0. A page beyond the available results is also an empty array. Tied sort values use ID ascending. Reset to page 1 when a filter changes.

6. Reuse a small fetch client

Download api.js into your frontend folder (the same folder as your index.html). Load your script with <script type="module" src="app.js"> — the type="module" is required for import and export to work. Remember to serve over HTTP, not file://.

import { createClient, APIError } from "./api.js";
const api = createClient("http://localhost:8080");

async function practice() {
  try {
    const { data: product } = await api.create({ name: "Pen", price: 2 });
    await api.get(product.id);
    await api.patch(product.id, { price: 0 });
    await api.replace(product.id, { name: "Blue pen", price: 3, description: "" });
    const { data, meta } = await api.list({ page: 1, limit: 5 });
    console.log(data, meta);
    await api.remove(product.id);
  } catch (error) {
    if (error instanceof APIError) {
      console.error(error.message, error.details);
    } else {
      console.error("Check the API connection", error);
    }
  }
}
practice();

The helper checks response.ok: fetch resolves even when HTTP returns 404 or 422. It also skips JSON parsing for 204, and passes an optional AbortSignal to list/get requests. See MDN’s Fetch guide for the browser behavior.

7. Practice the full experience

  1. Build a list with loading, error, and empty states.
  2. Add a form. Convert the price from a nonempty input string to a number, and show server field errors.
  3. Disable Save while a request is pending; restore it in finally.
  4. Add editing and deletion. Refresh after success and handle a product that another client deleted.
  5. Add search and pagination. Cancel outdated reads so old results cannot overwrite new ones.
  6. Use Network throttling or stop the server to practice connection errors and recovery.

Render user content with textContent or escaped framework bindings. Do not retry POST automatically after a lost connection: a write may already have succeeded. Refresh before submitting again.

This is a local learning API with shared data and no authentication. CORS is not authorization. Public deployment needs access control and per-user isolation. Prices preserve the original REAL storage; exact money calculations should use minor units or decimals with an explicit currency.
